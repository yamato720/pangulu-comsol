# S 工作流差距研究快照

本开发快照为 **0.7.0.dev1**，基于 `ae57500` 的 GPU 驻留实现，另含 PanguLU 正式用名更正。本版保存研究材料，没有新增数值优化；PanguLU SDK 继续使用原始 26.46，未换厂商库或许可。

## 已有结果

结果见 [../../results/s-gap/report.txt](../../results/s-gap/report.txt)。本机为 RTX 4080 Laptop、300475 阶 S 模型、8 线程。不能把这一结果直接外推到另一台机器的 1036043 阶模型。

- 完整扫频的存储 CSR 图变化 58 次，当前严格策略下双方均请求 59 次分析。
- 固定图对照采用同一图及 1.00/1.01 交替系数，区分“每轮分析”和“一次分析后重分解”，每种配置三个独立进程。
- CUPTI GPU 时间与普通 API/应用墙钟分开统计。原生 cuDSS API 可异步返回，不能把其主机返回耗时当 GPU 执行时间。
- 本机不加载 PanguLU 的 CUDA IPC 最小程序也返回 400；成功对比使用 direct，不宣称 worker GPU 路径已通过。

## 执行端使用

这些是原调查脚本，仍保留本机的模型、CUPTI、旧结果基线及矩阵路径，**不是另一台机器的通用安装器**。由执行端 Codex 按其环境调整即可。

先把脚本复制到新的 `data/runs/<本次目录>/`，保持与原实验相同的目录深度；结果统一写入 `data/`，不要在开发源码目录生成模型、矩阵或大日志。`profile.py` 的最终准备流程已采用正常外部后端 DSO 依赖加载观察器，不调用被 COMSOL Java 沙箱拒绝的 getenv/System.load 路径，也不改安全偏好。

执行前核对：

1. 本机 COMSOL、CUDA、SDK 与设备许可由正常 CLI 配置，生产组件先构建且 `device_csr=true`。
2. 修改 `CUPTI`、输入工程、固定矩阵 `PAIR` 和旧结果基线的位置；Java 助手的模型标签也需与目标模型一致。
3. 原 S 数据另行提供；本分支不包含 SDK、许可、MPH、矩阵原件或二进制追踪。
4. 先小频点验证，再完整 59 点。保留完成标记、实际库映射、CPU 参考、有限性及输入哈希检查。

`report.py` 中对旧本机报告的引用也须调整。成功的源文件和构建方法已保存；运行记录中的旧路径仅供溯源，不代表目标端的目录布局。
